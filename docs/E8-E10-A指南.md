# E8–E10 A组：执行与分工

本目录接入老师 2026-10-31 教学实验包中的受限 C/Make 参考实现。`labs/e8e10/lab.py` 的 A 路线用 GCC `-MM` 进行依赖分析、签名复用和保守刷新；E8、E10 另外调用实验包内的真实 BuildChecker 做动态交叉核对。它不是论文完整实现，也不是 E2 异步 Job API。原 E5–E7 服务及共享契约保留。

## 组长准备

本分支基于 A 组 main `7ffd57a`。先审查导入差异、验证结果和源文件归属，再按本组 GitLab 流程创建合并请求；教师材料中的 GitHub Actions 和 `gh` 认证命令不能直接当成 GitLab CI 结果。公共仓库是共享契约镜像，本次不直接修改其 main。实验包同时含 B 路线，供参考和原始测试使用，B 组的个人实验与交付由 B 组完成。

在 Linux 服务器上、本人独立克隆的仓库根目录设置真实学号作为 Git 本地用户名，设置本人邮箱，然后执行：

```bash
git config --local user.name '<本人学号>'
git config --local user.email '<本人邮箱>'
python3 run_lab.py build
python3 run_lab.py e8 --track A --out work/e8-A-001
python3 run_lab.py e9 --track A --out work/e9-A-001
python3 run_lab.py e10 --track A --out work/e10-A-001
```

每次使用尚不存在的新输出目录，勿覆盖证据。构建可能需要联网，实验容器运行时禁网。教师提供的分步路线请查看原材料的 `02_操作手册/8_E8_A组.md`、`9_E9_A组.md`、`10_E10_A组.md`；`classroom_helpers.sh` 可用于分步记录。

E8 核对真实 BuildChecker 产生的 trace、Make 数据库及基线，未变化时复用历史图。E9 核对 C0–C3 的真实样例提交、复用与刷新以及 MD/RD 的新增和消除。E10 核对六种变化各五次的增量与全量 actual、declared、findings 集合，保存 30 行原始计时并分别统计中位数，再核对最终 BuildChecker 动态结果。计时是教学扫描耗时，并非完整 clean build 耗时；不得把教师示例的结果写成本人结果。一键入口增加保存五对原始 JSON 及性能汇总，与老师的逐步手册验收材料对应。

## 每位组员各自完成

1. 使用自己的学号目录、仓库身份和个人分支运行 E8、E9、E10；保存本人源码 SHA、镜像 ID、实际命令、输出目录和日志。样例项目内的 C0–C3 SHA 与外层源码 SHA 要分开记录。
2. 基于独立预期增加测试或实现，并在新的输出目录验证。间接 include、文件删除或配置变化可作为选题；组员应分别说明实际贡献，不重复冒领相同更改。
3. 填写个人报告、ADR、AI 使用记录，说明输入、预期、实际结果、耗时统计及所改代码。教师的模板在实验包 `04_模板/`。
4. 在个人分支提交代码与报告，向组长发起 GitLab 合并请求；将 work 证据按课程要求单独归档，检查结果必须对应实际提交 SHA。不要提交真实凭据。

组长负责组织模板接入、审查各成员贡献和安排合并；不能代替其他成员虚构独立实验、提交或结果。A/B 对接真实产物属于后续集成；共享契约变更须双方核对。
